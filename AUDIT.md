## 1. Executive summary

Проект — **интерпретатор и C-транспилятор** учебного языка `.alg`. Пайплайн: **Lexer → Parser → AST → SemanticAnalyzer → Interpreter | CTranspiler**.

Пункты ниже (§2–§7) относятся к **раннему** состоянию прототипа и отмечены как выполненные. Актуальная картина возможностей и ограничений — в README / GRAMMAR; доработки 2026 (CRLF, builtins, break/continue, C-прототипы, SHAYDBG step\*) — в TODO_2026.

## 3. Архитектурные проблемы

- **Стиль:** классический компиляторный пайплайн (Lexer → Parser → AST → Visitor). Один общий AST для интерпретатора и транспилятора — нормально; разделение по типам посетителей соблюдается.
- **Границы ответственности:**
  - Интерпретатор одновременно выполняет роль семантического анализа (проверка типов, объявлений, областей видимости) и рантайма. Нет отдельного прохода семантики (типы, множественные объявления, вызовы) перед выполнением.
  - В парсере смешаны грамматика и эвристики (например, различение «объявление после нач» и «оператор» по заглядыванию вперёд в `block()`), что усложняет поддержку и перенос на другую грамматику.
- **Связанность:**
  - ✅ Загрузка модулей вынесена в `module_loader.load_alg_file()`; интерпретатор и транспилятор используют его вместо прямого вызова Lexer/Parser.
  - `parser` делает `from ast_nodes import *` и использует узлы по имени; `ast_nodes` не импортирует `TokenType`, но использует его в `Bool` — обратная зависимость по данным (типы токенов) без явного импорта.
- **SOLID:**
  - **S:** Встроенные функции вынесены в модуль `alg_builtins.py`; загрузка модулей — в `module_loader.py`.
  - **O:** Добавление нового узла AST или новой встроенной функции требует правок в нескольких местах (парсер, интерпретатор, транспилятор) — открытость ограничена.
  - **D:** Зависимости от конкретных классов (Lexer, Parser, конкретные узлы) не абстрагированы; DI нет, тестировать компоненты по отдельности сложно.
- **Циклические зависимости:** Прямых циклов импортов нет. В `ast_nodes` добавлен явный импорт `TokenType` из `lang_tokens` (циклов не возникает).
- **Разделение слоёв:** Лексер/парсер/AST выглядят отделёнными; слой «семантика» и слой «рантайм» в интерпретаторе объединены. Транспилятор повторяет часть семантики (типы) у себя в `var_types` вместо использования единого представления типов из AST/семантического прохода.

## 4. Технический долг

- **Тесты:** в `test_basic.py` — тесты лексера, парсера, интерпретатора, загрузчика модулей, интеграция (транспиляция в C, вызов main.py --transpile), интеграционный тест компиляции GCC и запуска exe (при наличии gcc).
- **Мёртвый/полумёртвый код:**
  - Файловый I/O в C реализован (FILE*, fopen/fclose, fprintf/fscanf).
  - Runtime-хелперы `NumberArray`, `String` в C объявлены, но в текущем сгенерированном коде не используются (используются только примитивы и массивы `double[]`).
- **Дублирование:**
  - Маппинг типов ALG → C в транспиляторе (см. выше).
  - ~~Логика «следующий токен» в парсере~~ — **выполнено:** введён метод `lookahead(offset=1)` с проверкой границ.
- **Слабая типизация и контракты:** Добавлены аннотации типов в main.py, version.py, errors.py, module_loader.py; контракты встроенных функций по-прежнему проверяются вручную в `_check_arity`.
- **Документация:** README, requirements.txt, **GRAMMAR.md** (описание грамматики и семантики); версия 1.0.1 в README.

## 5. Рекомендации по рефакторингу

1. **Исправить критические баги:** ✅  
   - В `ast_nodes.py` добавлен `from lang_tokens import TokenType`.  
   - В интерпретаторе `_built_in_eof` переведён на `tell()`/`read()`/`seek()` для текстовых файлов.  
   - В парсере введён метод `lookahead(1)` с проверкой границы, все обращения к следующему токену переведены на него.

2. **Вынести общую логику:** ✅  
   - Единый маппинг типов: метод `_c_type(type_node, string_const)` в транспиляторе.  
   - Загрузка модулей: модуль `module_loader.py`, функция `load_alg_file(filepath)` → AST; интерпретатор и транспилятор вызывают её при обработке `использовать`.

3. **Ужесточить обработку ошибок:** ✅  
   - В `main.py` добавлен общий `except Exception` с выводом сообщения и traceback.  
   - В `errors.py` добавлен `TranspilerError`; в C-транспиляторе `generic_visit` выбрасывает `TranspilerError` с указанием узла.

4. **C-генерация:** ✅  
   - Файловый I/O в C реализован: тип `файл`→FILE*, открыть/закрыть (fopen/fclose), вывод в файл (fprintf), ввод из файла (fscanf для чисел, fgets+strdup для лит).  
   - Для вывода выражений, содержащих `str_concat`/`num_to_str`, генерируется временная переменная, использование в printf и вызов `free()`.

5. **Безопасность и предсказуемость:** ✅  
   - В `utils.alg` для факториала при `n < 0` логика уже не рекурсивна; добавлен комментарий.

6. **Версионирование:** ✅  
   - Модуль `version.py` с `__version__ = "1.0.1"`. Версия используется в справке (при отсутствии аргументов и в `--help`), в баннере при интерпретации и транспиляции, в `--version`/`-v`.

7. **Инфраструктура:** ✅  
   - Добавлены `requirements.txt`, README, `test_basic.py` (тесты лексера и парсера; запуск: `python -m pytest test_basic.py`).  
   - При желании: тесты интерпретатора, интеграционный тест до C и запуска.
