## Принципы развития (обязательные условия)

Эти принципы **не подлежат компромиссу** при любой доработке проекта.

### П1. Самобытность языка `.alg`

- Проект **не** стремится к совместимости с классическим ШАЯ (Кушниренко и др.).
- Синтаксические отличия (`таб` вместо `мас`, `использовать`, `словарь`, `запись`, `переч` и т.д.) — **намеренные**, не дефекты.
- Документация должна позиционировать `.alg` как **самостоятельный учебный язык**, а не «подмножество ШАЯ».
- Задачи на «приведение к ШАЯ» в этот план **не включены**.

### П2. Максимальная информативность

- Сообщения об ошибках — подробные, на русском, с контекстом (строка, столбец, фрагмент кода, стек вызовов).
- Режим `--verbose` / `-v` для трассировки этапов: лексер → парсер → семантика → выполнение / транспиляция.
- Предупреждения (переопределения, неявные преобразования типов, устаревший синтаксис) выводятся **явно**, не глотаются.
- Verbose-режим распространяется на загрузку модулей, открытие файлов, вызовы процедур (опционально, по флагу).

### П3. Полный доступ к ресурсам системы (без sandbox)

- Программы на `.alg` **не ограничиваются** в доступе к файловой системе, сети (через внешние утилиты), системным каталогам.
- Путь к файлу в `открыть(f, путь, режим)` принимается **как есть**: абсолютный, относительный, `C:\Windows\System32\drivers\etc\hosts`, `/etc/passwd` и т.д.
- **Запрещено** вводить: whitelist каталогов, запрет `..`, chroot, виртуальную ФС, «безопасные» обёртки над `open`/`fopen`.
- Сгенерированный C-код использует прямой `fopen` без фильтрации путей.
- В README и GRAMMAR.md явно указать: среда выполнения доверяет программе полностью; ответственность за пути — на авторе программы и преподавателе.
