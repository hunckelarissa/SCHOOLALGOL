## 1. Введение и цели аудита

Цель аудита — глубокий анализ всей кодовой базы **SCHOOLALGOL** (`.alg`):
- Лексический, синтаксический и семантический анализ;
- Интерпретатор и виртуальная машина рантайма;
- C-транспилятор и паритет с компилируемым кодом;
- Протокол пошаговой отладки SHAYDBG и взаимодействие с Eclipse IDE;
- Стандартная библиотека и математический аппарат;
- Инфраструктура тестов, сборок и CLI.

## 2. Результаты анализа: чего не хватает для полноценной работы

### 2.1. Критические дефекты и баги существующего кода
1. **Сбои лексера на Windows (CRLF)**: В `lexer.py` регулярные выражения для пропуска и переводов строк (`SKIP`, `NEWLINE`) не учитывают `\r`. При открытии любого файла со стандартными переводами строк Windows `\r\n` лексер падает с `LexerError: Неожиданный символ '\r'`.
2. **Пропуск вызова `void`-процедур в выражениях в статическом анализаторе**: В `semantic_analyzer.py` метод `_check_subroutine_call(expr, allow_void=False)` принимает аргумент `allow_void=False`, но никак его не проверяет для пользовательских процедур `ProcDecl` и встроенных процедур (`закрыть`, `открыть`). В результате код `x := МояПроцедура(1)` успешно проходит проверку `main.py --check`, генерирует некомпилируемый код в C и падает только в интерпретаторе.
3. **Некорректное сравнение строк в C-транспиляторе**: В `c_transpiler.py` для операторов `=` и `<>` при сравнении строк генерируются поинтерные `==` и `!=` вместо вызова `strcmp`. В C сравнение указателей для строк на куче/в литералах дает ложные результаты.
4. **Необъявленные переменные циклов в C-транспиляторе**: По стандарту языка переменная цикла `нц для i от 1 до 5` может быть не объявлена явно (в интерпретаторе создается с `ImplicitDeclareWarning`). В C-транспиляторе локальная переменная `i` не объявляется, что вызывает ошибку компиляции GCC (`'i' undeclared`).
5. **Утечки памяти и aliasing строк в C**: При присваивании `s1 := s2` для строковых переменных в C генерируется `s1 = s2;` без освобождения старого значения `s1` и без создания копии `strdup(s2)`.
6. **Конфликт модулей pytest при запуске тестов**: Отсутствует файл конфигурации `pytest.ini`, из-за чего запуск `python -m pytest` в корне репозитория падает при попытке собрать тесты из `Gemini_reference/`.

### 2.2. Пробелы в ядре языка и стандартной библиотеке
1. **Отсутствие целочисленного деления и остатка от деления**: В учебном алгоритмическом языке отсутствуют базовые функции `остаток(a, b)` / `mod(a, b)` и `целдел(a, b)` / `div(a, b)`. Без них невозможно решать типовые школьные и олимпиадные задачи (четность, разбор чисел по разрядам, НОД/алгоритм Евклида).
2. **Отсутствие базовых математических функций**:
   - `степень(a, b)` / `pow(a, b)` (и возведение в степень);
   - `мин(a, b)` / `min(a, b)`, `макс(a, b)` / `max(a, b)`;
   - `округление(x)` / `round(x)`, `знак(x)` / `sign(x)`;
   - `sin(x)`, `cos(x)`.
3. **Отсутствие функций для работы с коллекциями и строками**:
   - Нет функции определения размера массива: `размер(arr)` / `len(arr)`;
   - Нет функции поиска в строке: `найти(str, substr)` / `find(str, substr)`.
4. **Отсутствие оператора прерывания цикла**:
   - В языке нет оператора досрочного выхода из цикла: `выход` / `break`. Это критически важная конструкция алгоритмического языка.

### 2.3. Пробелы в подсистеме отладки (SHAYDBG)
1. **Отсутствие дифференциации шагов отладчика**: Команды `step`, `step_over`, `step_into`, `step_out` в `interpreter.py` работают одинаково (останавливаются на первой следующей строке). Step Over проваливается внутрь функций, а Step Out не дожидается возврата из функции. Необходим учет глубины стека вызовов (`call_stack_depth`).

### 2.4. Эргономика CLI
1. **Поддержка явного флага `--run`**: Скрипт `shaya-run.bat` оперирует режимами `--run`, `--check`, `--debug`. При прямой передаче `--run` в `main.py` CLI выдавал ошибку неизвестного аргумента.
